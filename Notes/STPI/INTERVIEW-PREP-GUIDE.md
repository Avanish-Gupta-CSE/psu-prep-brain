## 🧮 SECTION C: DATA STRUCTURES & ALGORITHMS

### 1. Stack vs Queue
*   **Stack**: Follows **LIFO** (Last In, First Out). Operations (`push`, `pop`) occur at one end (top). Used in function calls, recursion, and undo mechanisms.
*   **Queue**: Follows **FIFO** (First In, First Out). Operations occur at two ends: insertion at `rear` (`enqueue`), deletion at `front` (`dequeue`). Used in CPU scheduling, printer queues, and BFS.

### 2. BFS vs DFS
*   **BFS (Breadth-First Search)**: Explores a graph level-by-level. Uses a **Queue**. Finds the shortest path in unweighted graphs. Time Complexity: $O(V + E)$, Space Complexity: $O(V)$.
*   **DFS (Depth-First Search)**: Explores as deep as possible along each branch before backtracking. Uses a **Stack** (or recursion). Used for topological sorting and cycle detection. Time Complexity: $O(V + E)$, Space Complexity: $O(V)$.

### 3. HashMap vs TreeMap
*   **HashMap**: Backed by a Hash Table. Unordered. Offers **$O(1)$ average** time complexity for search, insertion, and deletion. Allows one null key.
*   **TreeMap**: Backed by a Red-Black Tree (Self-balancing BST). Sorted order. Offers **$O(\log n)$** time complexity for search, insertion, and deletion. Does not allow null keys.

### 4. Binary Search
An efficient algorithm for finding an element in a **sorted** array. It repeatedly divides the search interval in half.
*   **Time Complexity**: $O(\log n)$ (Best: $O(1)$).
*   **Space Complexity**: $O(1)$ (iterative) or $O(\log n)$ (recursive due to call stack).

### 5. Time complexity of Merge Sort
*   **Worst, Average, and Best Case**: **$O(n \log n)$**.
*   **Explanation**: The array of size $n$ is divided into halves $\log n$ times (tree height is $\log n$), and merging the sub-arrays at each level takes $O(n)$ time.

### 6. Quick Sort vs Merge Sort
*   **Quick Sort**: In-place sorting algorithm (Space: $O(\log n)$). Unstable. Average time: $O(n \log n)$, Worst-case: $O(n^2)$ (when pivot is poorly chosen). Highly cache-friendly.
*   **Merge Sort**: Out-of-place sorting algorithm (requires $O(n)$ auxiliary space). Stable. Guaranteed $O(n \log n)$ time in all cases. Preferred for linked lists and large datasets (external sorting).

### 7. AVL Tree
A **strictly self-balancing** Binary Search Tree where the difference between heights of left and right subtrees (Balance Factor) for any node is at most **1, 0, or -1**. If unbalanced, it performs rotations (LL, RR, LR, RL).
*   **Lookup/Insert/Delete**: Guaranteed $O(\log n)$. More strictly balanced than Red-Black trees, making it faster for lookups but slower for insertions/deletions due to frequent rotations.

### 8. Heap Applications
*   **Priority Queues**: Implementing task scheduling in operating systems.
*   **Heap Sort**: An in-place sorting algorithm with guaranteed $O(n \log n)$ time.
*   **Graph Algorithms**: Dijkstra's shortest path and Prim's Minimum Spanning Tree (using Min-Heaps to quickly extract the minimum weight edge).
*   **K-way Merge / Finding Median**: Efficiently finding the $k$-th largest/smallest element in a stream.

### 9. Dynamic Programming (DP)
An algorithmic paradigm that solves a complex problem by breaking it down into simpler subproblems, solving each subproblem **exactly once**, and storing their solutions (using memoization or tabulation) to avoid redundant computations.
*   **Key Properties**: Overlapping Subproblems and Optimal Substructure.

### 10. Dijkstra Algorithm
Finds the shortest path from a single source node to all other nodes in a weighted graph with **non-negative edge weights**.
*   **Mechanism**: Uses a Greedy approach, maintaining a set of visited nodes and a Min-Priority Queue of distances.
*   **Time Complexity**: $O((V + E) \log V)$ using a Binary Heap.

## ⚡ SECTION D: OPERATING SYSTEM

### 1. Process vs Thread
*   **Process**: An executing program with its own independent address space, memory, file descriptors, and security context. Context switching is heavy.
*   **Thread**: A lightweight unit of execution within a process. Threads share the process's memory (code, data, heap) but have their own stack and registers. Context switching is fast.

### 2. Deadlock
A state where a set of processes are blocked because each process holds a resource and waits for another resource held by some other process in the set.
*   **4 Necessary Conditions (Coffman Conditions)**:
    1.  **Mutual Exclusion**: Resources cannot be shared.
    2.  **Hold and Wait**: A process holds a resource while waiting for another.
    3.  **No Preemption**: Resources cannot be forcibly taken.
    4.  **Circular Wait**: A closed chain of processes exists where each waits for the next.

### 3. Paging vs Segmentation
*   **Paging**: Divides physical memory into fixed-size blocks (frames) and logical memory into pages of the same size. Eliminates **external fragmentation** but can cause **internal fragmentation**. Non-contiguous.
*   **Segmentation**: Divides logical memory into variable-size segments based on the user's view (functions, objects, stack). Eliminates internal fragmentation but can cause **external fragmentation**.

### 4. Virtual Memory
A memory management technique that allows the execution of processes that are not completely in physical memory. It maps logical addresses to physical addresses, giving the illusion of a much larger RAM by utilizing secondary storage (disk swapping).

### 5. Context Switching
The process of storing the state (context) of a CPU register/process/thread so that it can be paused and resumed later, allowing multiple processes to share a single CPU. It involves saving the PCB (Process Control Block) and loading a new one.

### 6. Scheduling Algorithms
*   **First-Come, First-Served (FCFS)**: Non-preemptive, simple, prone to Convoy Effect.
*   **Shortest Job First (SJF)**: Gives optimal average waiting time; prone to starvation for long jobs.
*   **Round Robin (RR)**: Preemptive, uses time slices (quanta). Excellent for time-sharing systems.
*   **Priority Scheduling**: Preemptive/Non-preemptive; high-priority tasks run first; solved via **Aging** to prevent starvation.

### 7. Mutex vs Semaphore
*   **Mutex (Mutual Exclusion)**: A locking mechanism. It is **owner-based**—only the thread that locked the mutex can unlock it. Value is binary (0 or 1).
*   **Semaphore**: A signaling mechanism. It has no concept of ownership.
    *   *Binary Semaphore*: Value is 0 or 1 (any thread can signal/unlock it).
    *   *Counting Semaphore*: Value represents available resource instances (e.g., database connection pool).

### 8. Producer-Consumer Problem
A classic multi-process synchronization problem. A producer thread places data into a fixed-size buffer, and a consumer thread removes it.
*   **Solution**: Uses semaphores to prevent race conditions: `mutex` (for mutual exclusion on buffer access), `empty` (counting semaphore for empty slots), and `full` (counting semaphore for filled slots).

### 9. Race Condition
An undesirable situation that occurs when multiple threads/processes access and manipulate shared data concurrently, and the final outcome depends on the non-deterministic order of execution. Prevented using critical section synchronization (locks, mutexes).

### 10. Starvation vs Deadlock
*   **Starvation**: A process is perpetually denied the resources it needs to execute because other processes are continuously prioritized. The system is still running, but one process is frozen.
*   **Deadlock**: A complete system freeze where multiple processes are mutually waiting for each other, and **no process** can make progress.

## 💾 SECTION E: DBMS

### 1. ACID Properties
*   **Atomicity**: "All or nothing." Either the entire transaction succeeds, or it is completely rolled back.
*   **Consistency**: A transaction transforms the database from one valid state to another, maintaining all schema constraints.
*   **Isolation**: Concurrent execution of transactions results in a state equivalent to serial execution.
*   **Durability**: Once committed, the changes are permanently written to non-volatile storage and survive system crashes.

### 2. Normalization
The process of organizing data in a database to reduce data redundancy and eliminate update, insertion, and deletion anomalies.
*   **1NF**: Atomic values, no repeating groups.
*   **2NF**: In 1NF + no partial dependency (every non-prime attribute must be fully functionally dependent on the primary key).
*   **3NF**: In 2NF + no transitive dependency (non-prime attributes cannot determine other non-prime attributes).
*   **BCNF**: Strict version of 3NF; for every functional dependency $X \rightarrow Y$, $X$ must be a super key.

### 3. SQL Joins
*   **INNER JOIN**: Returns records that have matching values in both tables.
*   **LEFT (OUTER) JOIN**: Returns all records from the left table and matched records from the right table (unmatched right records result in `NULL`).
*   **RIGHT (OUTER) JOIN**: Returns all records from the right table and matched records from the left table.
*   **FULL (OUTER) JOIN**: Returns all records when there is a match in either left or right table.

### 4. Indexing
A data structure technique (usually using B+ Trees) used to quickly locate and access data in a database table without scanning the entire table (Full Table Scan). It drastically speeds up `SELECT` queries but adds write overhead on `INSERT/UPDATE/DELETE`.

### 5. Primary Key vs Foreign Key
*   **Primary Key**: Uniquely identifies a record in a table. Cannot contain `NULL` values. Only one allowed per table.
*   **Foreign Key**: A field in one table that uniquely identifies a row of another table (establishes a relationship). Can contain `NULL` values and duplicate entries.

### 6. Clustered vs Non-clustered Index
*   **Clustered Index**: Determines the physical order in which data is stored on disk. Only **one** clustered index can exist per table (usually the Primary Key).
*   **Non-clustered Index**: Stores a separate index structure containing keys and pointers to the actual data rows. Multiple non-clustered indexes can exist on a single table.

### 7. Transactions
A logical unit of work in a database containing one or more SQL statements executed as a single block. It begins with `BEGIN TRANSACTION` and ends with either a `COMMIT` (permanent save) or a `ROLLBACK` (undo all changes).

### 8. Views
A virtual table based on the result-set of an active SQL query. It does not store physical data (unless it is a Materialized View). Used to simplify complex queries, restrict data access for security, and provide a clean interface.

### 9. Stored Procedures
A prepared SQL code block that is compiled and stored in the database, which can be saved and reused. It supports input/output parameters, conditional logic, and transactions, reducing network traffic between the application and database.

### 10. SQL Query Writing (High-Yield Patterns)
*   **Find Second Highest Salary**:
    ```sql
    SELECT MAX(Salary) FROM Employee 
    WHERE Salary < (SELECT MAX(Salary) FROM Employee);
    ```
*   **Group By & Having (Find duplicate emails)**:
    ```sql
    SELECT Email, COUNT(Email) FROM Users 
    GROUP BY Email HAVING COUNT(Email) > 1;
    ```

## 🌐 SECTION F: COMPUTER NETWORKS

### 1. OSI Model
A 7-layer conceptual framework developed by ISO to standardize network communications:
1.  **Physical**: Transmission of raw unstructured bits over physical medium.
2.  **Data Link**: Node-to-node data transfer, framing, MAC addressing, error control.
3.  **Network**: Routing, logical addressing (IP), packet forwarding.
4.  **Transport**: End-to-end connection, flow control, segmentation, error recovery (TCP/UDP).
5.  **Session**: Managing, establishing, and terminating sessions between applications.
6.  **Presentation**: Data translation, encryption, compression, formatting.
7.  **Application**: Human-computer interaction, network services (HTTP, FTP, SMTP).

### 2. TCP vs UDP
*   **TCP (Transmission Control Protocol)**: Connection-oriented, reliable (guarantees delivery via ACKs), ordered, slow, performs flow and congestion control. Used in HTTP, HTTPS, SSH, FTP.
*   **UDP (User Datagram Protocol)**: Connectionless, unreliable, unordered, extremely fast, lightweight. Used in DNS, video streaming, VoIP, online gaming.

### 3. HTTP vs HTTPS
*   **HTTP**: Unsecured. Transmits data in plain text over port **80**. Vulnerable to eavesdropping and man-in-the-middle attacks.
*   **HTTPS**: Secured. Encrypts data using **SSL/TLS** over port **443**. Ensures confidentiality, integrity, and authentication.

### 4. DNS (Domain Name System)
The "phonebook of the Internet." It translates human-readable domain names (e.g., `stpi.in`) into machine-readable IP addresses (e.g., `164.100.x.x`) over port **53** (primarily UDP).

### 5. DHCP (Dynamic Host Configuration Protocol)
A network management protocol used to dynamically assign IP addresses, subnet masks, default gateways, and DNS servers to devices on an IP network, operating on ports **67** and **68** (UDP).

### 6. Routing
The process of selecting the optimal path for network traffic (packets) across one or multiple networks from a source to a destination. Handled by routers using routing protocols (OSPF, BGP, RIP) at the Network Layer.

### 7. IPv4 vs IPv6
*   **IPv4**: 32-bit address space ($2^{32}$ addresses). Written in dotted-decimal format (e.g., `192.168.1.1`). Requires NAT to handle address exhaustion.
*   **IPv6**: 128-bit address space ($2^{128}$ addresses). Written in hexadecimal format (e.g., `2001:db8::ff00:42:8329`). Built-in security (IPsec) and eliminates the need for NAT.

### 8. TCP Three-way Handshake
The process used to establish a reliable TCP connection:
1.  **SYN**: Client sends a packet with `SYN` flag set and an Initial Sequence Number ($x$) to the server.
2.  **SYN-ACK**: Server acknowledges by sending a packet with `SYN` and `ACK` flags set, acknowledging $x+1$ and sending its own sequence number ($y$).
3.  **ACK**: Client acknowledges by sending an `ACK` packet with sequence number $x+1$ and acknowledgment number $y+1$.

### 9. Firewall
A network security device that monitors and filters incoming and outgoing network traffic based on an organization's previously established security policies. It acts as a barrier between a trusted internal network and an untrusted external network.

### 10. VPN (Virtual Private Network)
A technology that creates a safe, encrypted connection (tunnel) over a less secure network, such as the public Internet. It masks the user's IP address and encrypts all transmitted data, ensuring privacy and secure access to remote resources.

## 💻 SECTION G: PROGRAMMING

### 1. OOP Concepts
*   **Encapsulation**: Bundling data (variables) and methods that operate on them into a single unit (class) and restricting direct access (using private modifiers).
*   **Inheritance**: Mechanism where a new class (derived/child) acquires the properties and behaviors of an existing class (base/parent).
*   **Polymorphism**: "Many forms." The ability of a message or function to be processed in more than one way (Compile-time: Overloading; Runtime: Overriding).
*   **Abstraction**: Hiding complex implementation details and showing only the essential features to the user (using abstract classes and interfaces).

### 2. Polymorphism (Compile-time vs Runtime)
*   **Compile-time (Static)**: Resolved during compilation. Achieved via **Method Overloading** (same method name, different parameters) or Operator Overloading.
*   **Runtime (Dynamic)**: Resolved during execution. Achieved via **Method Overriding** (child class redefines a parent class method). The JVM/Compiler uses dynamic binding to call the correct method.

### 3. Virtual Functions
A function in a base class declared with the `virtual` keyword (in C++) that is overridden in a derived class. It ensures that the correct function is called for an object, regardless of the type of reference/pointer used to call it.
*   **Mechanism**: Handled via a **VTable** (Virtual Table) and **VPointer** (Virtual Pointer) at runtime.

### 4. Exception Handling
A mechanism to handle runtime errors (such as division by zero, null pointers, or file not found) so that the normal flow of application execution is maintained. Uses `try` (blocks risky code), `catch` (handles the exception), `throw` (explicitly triggers an exception), and `finally`/`cleanup` (always executes, e.g., closing connections).

### 5. Pointers
A variable that stores the direct physical memory address of another variable.
*   *C++ vs Java*: C++ supports direct pointer manipulation, arithmetic, and manual memory management. Java does not support explicit pointers or pointer arithmetic to ensure memory safety, instead using implicit object references.

### 6. Memory Leak
A situation where a program allocates memory dynamically on the heap but fails to release/deallocate it back to the operating system when it is no longer needed. Over time, this degrades system performance and can lead to out-of-memory crashes.

### 7. Multithreading
A programming concept where an application is divided into two or more concurrent execution blocks (threads) running in parallel. It maximizes CPU utilization, especially in multi-core processors.

### 8. Garbage Collection
An automatic memory management process in modern runtimes (like Java's JVM or .NET's CLR) that periodically identifies and deletes objects on the heap that are no longer reachable or referenced by the application, preventing manual memory leaks.

### 9. Java vs C++
*   **Compilation**: C++ is compiled directly to platform-dependent machine code. Java is compiled to platform-independent **Bytecode**, which is interpreted/compiled by the JVM (using JIT).
*   **Memory**: C++ requires manual memory management (`new`, `delete`). Java has automatic Garbage Collection.
*   **Multiple Inheritance**: C++ supports multiple inheritance of classes. Java does not support multiple inheritance of classes (to prevent the Diamond Problem) but allows it through Interfaces.
*   **Pointers**: C++ has explicit pointers. Java has implicit references.

### 10. Python Advantages
*   Highly readable, clean, and concise syntax (increases developer productivity).
*   Dynamically typed with automatic memory management.
*   Massive standard library and ecosystem, especially for **AI, Machine Learning, Data Science, and Scripting**.
*   Excellent cross-platform compatibility and rapid prototyping capabilities.

## ☁️ SECTION I: IMPORTANT CORE TOPICS

### 1. CLOUD COMPUTING
*   **IaaS (Infrastructure as a Service)**: Provides raw computing resources (servers, storage, networking). User manages OS, middleware, and applications. (e.g., AWS EC2, Azure VMs).
*   **PaaS (Platform as a Service)**: Provides a managed platform with OS, runtime, and database. User only manages application code. (e.g., Azure App Service, Heroku).
*   **SaaS (Software as a Service)**: Fully managed end-user software delivered over the web. (e.g., Microsoft 365, Salesforce).
*   **Virtualization**: The technology that allows partitioning a single physical server into multiple isolated virtual machines (VMs) using a **Hypervisor** (Type 1: Bare-metal like ESXi; Type 2: Hosted like VirtualBox).
*   **Scalability**:
    *   *Vertical (Scale Up)*: Adding more power (CPU, RAM) to an existing server.
    *   *Horizontal (Scale Out)*: Adding more servers to the pool (handled via Load Balancers).

### 2. ARTIFICIAL INTELLIGENCE & MACHINE LEARNING
*   **Supervised Learning**: Model is trained on labeled data (input-output pairs). Used for Classification (e.g., spam detection) and Regression (e.g., predicting house prices).
*   **Unsupervised Learning**: Model is trained on unlabeled data to find hidden patterns. Used for Clustering (e.g., customer segmentation) and Anomaly Detection.
*   **Neural Networks**: Computational models inspired by the human brain, consisting of interconnected layers of nodes (neurons): Input Layer, Hidden Layers, and Output Layer. Used in Deep Learning for complex pattern recognition (images, audio).
*   **Generative AI & LLMs**:
